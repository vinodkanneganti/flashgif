# ADR-38: 404 (not 403) for ownership/visibility failures

**Status:** Accepted
**Date:** 2026-05-21 (Slice 4)
**Tags:** backend, security, api

## Context
Private collections and not-yet-published media exist in the same URL space as public resources. A naive design returns 403 when the caller isn't allowed to see them — which is exactly the signal an attacker needs to confirm "this resource exists, you just can't see it".

## Decision
Ownership and visibility failures return **404 Not Found**, not 403. The service layer raises a single not-found exception in two cases:
1. The resource genuinely doesn't exist.
2. The resource exists but the caller doesn't own it / isn't allowed to see it.

Controllers don't distinguish; both surface as 404.

## Rationale
- Standard practice — GitHub, Stripe, Linear all do this for private resources.
- Hides the existence of private content from probing. No information leak via differentiated status codes.
- One exception type instead of two simplifies the service layer; the ambiguity is intentional and the right kind.

## Consequences
- Genuine 403s are reserved for "you authenticated but lack the role" — e.g., a non-admin hitting a future admin endpoint. Resource visibility never produces 403.
- Logs and metrics should distinguish the two internally for debugging — both being 404 to the client doesn't mean both should be 404 in the operator's view.
- Clients building error UI ("you don't have permission" vs "this doesn't exist") lose that distinction by design. The right UX is the same message either way: "not found".
